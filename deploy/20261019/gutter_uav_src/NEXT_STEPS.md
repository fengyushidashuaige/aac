## 1. v2 架构：定位融合做主体，视觉只做局部修正

```
层0  定位      LiDAR + GPS/RTK  →  世界系位姿      （替代 v1 的纯视觉外环）
层1  槽线建图   槽中心线  →  世界系折线            （离线标一次 / 在线维护）
层2  轨迹跟踪   沿折线 纯追踪  →  平滑速度/位置目标  （丝滑度由此层保证）
层3  视觉残差   图像槽中线 vs 预测投影 → Δ，低带宽(1~2Hz) 小修正
层4  飞控内环   姿态/高度/油门                     （PX4 OFFBOARD / 后续）
```

**核心设计决定**：视觉**不再承担外环的全部**，只输出残差；丝滑度由层2 的几何轨迹保证，与图像抖动解耦。

## 2. v1 为什么「一直在中间不丝滑」——根因诊断

> **2026-09-14 补充取证**：见文末 §8。实测**好会话噪声 σ≈5mm**，而 `dead_zone_mm=30` —— 死区是噪声的 6 倍，这是「一直在中间但不居中」的**直接原因**。

**结论：不是 PID 没调好，是结构性问题。** `dead_zone / angle_jump_streak / cruise_lock / 15mm 瞬移钳制 / vy_in_yaw_gate_scale` 这些 band-aid 是在压一个结构性振荡，越多越互相打架。

| # | 问题 | 证据（代码位置） |
|---|------|------------------|
| 1 | **mm/像素靠检测自估 → 乘性噪声** | `detector.py:1284` `mm_per_px = trough_width_mm(110) / trough_width_px`。检测宽度一抖，`offset_mm` 被整体缩放一抖 |
| 2 | **控制率 = 检测率**，无中间插值 | `main.py:872` `while True` + `sleep(0.001)`，每帧算一次发一次（~15~30Hz），全靠 `_slew` 兜；slew 只平滑，不解决相位滞后 |
| 3 | **纯延迟约 0.25s，滤波再叠滞后** | 自命名 `offset_pred_latency_s=0.25`；角度 EMA α=0.28（时间常数 ~3 帧）；`offset_dot` 用 `2.5×0.35 = 0.875s` 窗 polyfit —— **0.875 秒的微分早已失效，D 项形同虚设** |
| 4 | **vy 与 yaw 在 BODY_NED 下耦合** | 偏航一转，机体 vy 方向跟着转，而图像 offset 也是相对光轴的 → 互相串扰。用 `yaw_only_gate_deg>20 → vy×0.25` 硬压，压出来就是「摆一下、停一下」 |
| 5 | **无积分项** | `lateral_ki=0, yaw_ki=0`。恒定侧风/桨流/安装偏置永远消不掉 → 永远差一点 → 持续微摆 |
| 6 | **BEV 用固定高度** | `mount_height_m=1.0` 写死。实高变化（v1 记过「掉高」）→ mm/px 系统性偏 → 恒定偏置，回到第 5 条 |

## 3. 分档改造

### 档 0｜不改架构，几天，性价比最高
1. **mm/px 别再自估**：已有 BEV 透视（`perspective_out_height=600`），BEV 之后 mm/px 只由**高度**决定 → 用雷达/高度传感器给实高，`mm_per_px = f(h)`。干掉根因 1、6。
2. **帧时间戳对齐**：用 V4L2 采集时刻（非处理完时刻）打时间戳，MAVLink 带 `time_boot_ms`。省 30~60ms 相位滞后。
3. **拆控制率**：视觉 30Hz 更新目标，50Hz 插值/预测下发，别让飞控吃阶梯指令。
4. **微分窗砍到 0.15~0.25s**（或直接用滤波器 dot 输出），救回 D 项。
5. **离线回放闭环调参**：用 `~/logs/` 的 `raw_*.avi` 喂回 `detector + controller` 做闭环仿真，**增益在不开机情况下调收敛再上机**。v1 全靠「某日试 X 无收益」盲试飞（config 注释可见），最耗时。

### 档 1｜换控制律（治本）
- 横向误差**不要靠机体横移**纠正，改用 **Stanley / 纯追踪**类几何律，横向偏差转成航向修正：
  `yaw_rate = -(k_theta * theta_e + k_e * e / vx)`
  天然消掉根因 4，`yaw_only_gate` 那一套可删。
- 或**级联 + 时间尺度分离**：先快环把 `theta_e` 收 0，再慢环收 `e`。
- **补积分项**消稳态偏差（有了档 0 的尺度稳定，积分才敢加）。
- 指令从 BODY_NED 速度 → **LOCAL_NED 位置 + 偏航**（`SET_POSITION_TARGET_LOCAL_NED`，`type_mask = 3064`）。让飞控内环自己做轨迹插值——**单点收益最大的一招**。

### 档 2｜v2 新架构（雷达 + GPS 融合）
1. 雷达/RTK 把槽中心线建成**世界系折线**。
2. 主体控制 = 沿折线做**纯追踪**（几何量，与图像抖动无关，天然丝滑）。
3. 视觉只输出**残差 Δ** = 图像槽中线 vs 按世界系轨迹预测「本该出现的位置」，**低带宽（1~2Hz）**小修正。
4. 收益：视觉噪声/延迟被低带宽滤掉；丝滑度由轨迹决定。**架构与「水槽识别只做局部调整中心」的目标一致。**

## 4. ⚠️ 一等感知风险：吹风筒与水槽同色

**现象**：执行机构向前伸出一根**长吹风筒**，**白色、细长**，外观与白色水槽**相近**。

**风险**
| 编号 | 风险 | 后果 |
|------|------|------|
| R1 | **误检**：模型把吹风筒分割成水槽 | `offset_mm` / `angle_deg` 直接输出错值，控制律被喂假误差 |
| R2 | **遮挡**：筒挡住槽的一部分 | 中心线在遮挡段靠外推 → 系统性偏差 |
| R3 | **居中歧义**：筒若落在画面中心附近 | PCA 中心线可能被筒主导，「对准中心」的目标本身失真 |

> 注意：v1 那套「瞬移钳制 / jump_streak」在遇到 R1 时会**压制真值**，让错误更隐蔽——不是保护。

**对策（按优先级，M1 优先）**
| 编号 | 对策 | 成本 | 说明 |
|------|------|------|------|
| **M1** | **机械/安装优先**：把筒移出相机视野（改安装角 / 加遮光罩 / 筒体改**哑光深色**涂装） | 零算法成本 | **首选**。感知问题的最优解通常是别让它进画面 |
| M2 | **视野裁剪**：若筒在图像中位置固定，用 ROI / `ctrl_y_frac` 排除该区域 | 低 | 仅在 M1 不可行时 |
| M3 | **几何判据**：槽在地面平面、筒在近处（不在地面平面）→ BEV 逆投影后剔除非地面平面区域 | 中 | 依赖实高准确 |
| M4 | **模型侧**：把「吹风筒」作为负样本/独立类别做微调后排除 | 中 | 见第 5 节，需标注 |
| M5 | **融合侧**：上雷达后用点云几何定槽（两条边缘线），视觉只做亚像素精定位 | 高（但顺路） | **天然免疫同色干扰**，与档 2 同一条路 |

### 4.3 漏检根因：两道门限都过低


## 5. 换全局快门相机：要不要重训识别模型？

**结论：通常不用重训。** 但要分清「训练」与「标定/调参」。

### 为什么不用重训
- 快门方式不改变「水槽长什么样」，模型学的是外观/语义，不是运动畸变。
- **意外的好处**：mm/px 是**自估**的（`110mm / 检测宽度px`），FOV 变了会自动适配 → `offset_mm` 物理尺度大致不变 → 增益也不必大改。
- GS 图像比 RS 更干净，通常更接近自然分布，**退化风险反而更低**。

### 必须重做的（都不是训练）
| 项 | 为什么 |
|----|--------|
| 相机内参 + 畸变标定 | 新镜头畸变不同 → BEV 透视、`angle_deg` 都会变 |
| 曝光/增益/白平衡/对比度/锐度 | `config.py` 里那一大批。新传感器响应不同；GS 可上更长曝光，弱光更干净 |
| FOV / 安装角 / 高度 | `ctrl_y_frac=0.40`、`perspective_*`、`trough_width_mm=110` 相关几何要重核 |
| `infer_blur_ksize=3` | 这个糊是**专门「抗果冻」**用的（config 注释即写）。GS 不需要 → 关掉，mask 更锐、中心线更准 |
| 增益重核 | 尺度虽不变，但噪声/延迟特征变了，`kp/kd/死区`要复核 |

### 何时才需要微调（不是重训）
- 新 FOV 畸变大到中心线明显弯曲
- 新传感器色彩响应让 mask 塌掉
- 新场景（水面反光、新材质、新光照）
- **新增吹风筒干扰**（见第 4 节 R1）→ 需加负样本

### 判据流程（低成本）
1. 新相机采 **200~500 帧**典型场景
2. 跑现有 engine
3. 对比人工标注的中线，量 `e` / `theta` 的偏差与 **sigma**
   - sigma 没变差 → **什么都不用做**
   - 明显退化 → **冻结 backbone 微调 head**，几百张，半小时级
     （`models/` 里有 `gutter_seg_320.onnx.bak_ftbaseline`，说明 v1 已做过 fine-tune）

### 8.3 检测噪声实测（`[CTRL]` 行，帧间跳变 ≈ 噪声底）

| 会话 | 帧数 | offset σ | 帧间跳变 | >500mm | conf |
|------|------|----------|----------|--------|------|
| **08-19 15:04:52** | 3287 | **5 mm** | **5 mm** | 0% | **0.87** |
| 08-19 15:02 / 15:03 | 169 / 219 | 2 / 4 mm | 2 / 3 mm | 0% | 0.87 |

**结论**
1. **视觉链路能做到 σ = 5mm**（8-19 全检出、conf 0.87、3287 帧）。
   ⚠️ **重要限定（09-14 补查）**：该会话 `rng = 0.48m`（3287 帧恒定 0.47~0.51m），是**台架静置、镜头距槽约 0.5m** 的测量。所以 σ=5mm 是**静止台架的纯检测噪声底**，**不是闭环控制平滑的证据**，也不能直接外推到飞行（更远、在动、光照在变）。结论「30mm 死区过大」依然成立，但请勿把 5mm 当作飞行噪声预期。
   ⚠️ 另：`rng q=0` 是**常态**（8-19 有读数时 q 也是 0），q=0 不代表无数据；`rng=0.00m` 才是真无读数。
2. 坏会话 σ 高 **20~90 倍**，且高达 **90%** 的帧输出 ±500mm 的垃圾值 —— 这类帧会被 `max_ctrl_offset_mm=500` 限幅后**打满横移**，是那些会话「不丝滑」的真凶。
3. **`dead_zone_mm = 30` 是实测噪声 σ=5mm 的 6 倍。** 代码注释的设定理由是「σ~25mm 会把噪声推成真实位移」，但 8-19 实测 σ 仅 5mm ⇒ **死区在压制一个不存在的噪声**，代价是 `|offset| < 30mm 时拒绝修正`，无人机停在 ±30mm 带内来回蹭 —— **这就是「一直在中间但不居中」的直接原因**。
4. `dead_zone_deg = 2.5` 同理（好会话实测 ang σ = 0.5°，也是 5 倍）。
5. 同理，`15mm 瞬移钳制` 与重滤波也是按「噪声很大」设计的，在干净会话里退化为**纯相位滞后**。

### 8.4 由此修正的优先级（覆盖 §3 / §6 的顺序）

- **【新增·最高】现场实测 σ，把死区设成 ~2σ**（σ=5mm ⇒ 死区 ~10mm；角度同理 ~1°）。这是**最便宜、最直接**的「居中」修复，且不需要改架构。
- **【新增】垃圾帧门控**：`conf` 低或 `|offset| > 500mm` 的帧不应参与控制，直接丢帧走 hold，而不是限幅后照发。
- **【修正】§3 档 0 的「离线回放调参」**：`raw_*.avi` 已断供（§8.2），需先把 `save_raw_video` 改回 `True` 并重录素材，否则该任务无法开始。
- **【保留】§3 档 1 / 档 2** 不变；但注意档 1 的收益在「检测已干净」时会明显变小——先解决 8.3 的第 3 条，再评估还需不需要换控制律。

## 10. 光照域偏移风险（用户提出，2026-09-14）

**用户判断：太阳下画面与当前不同，检测会失效。已被 config 历史佐证。**

```python
# config_jetson.py:13
# 户外：手动曝光 exp=1/gain=95（2026-08-13 试飞用，8-12 户外实测组合）；室内台架换回 auto_exposure=True
cfg.camera.auto_exposure = True   # DECXIN DCGX200 定焦: 自动曝光(用户要求 08-19)
```

⇒ **当前生效的是「室内台架」配置**，户外需另一套。**拿台架参数跑户外大概率不行。**

### 太阳下具体失效模式

| 模式 | 机理 |
|------|------|
| **白槽过曝饱和** | 白槽+直射阳光 → 槽与亮地面同时打到 255，模型依赖的「白槽 vs 深色地面」对比消失 → mask 塌陷/漂移。**「白对白」典型死法** |
| **自动曝光来回追** | AE 逐帧调整，机体动/光变 → 曝光振荡 → 画面统计量帧帧变 → `conf` 忽高忽低。**控制环最怕测量忽好忽坏** |
| **动态范围不足** | 同帧内阳光与阴影并存 → 槽过曝或阴影死黑，不可兼得 |
| **水面镜面反光** | 槽内有水时阳光镜面反射成亮斑 → mask 可能被劈成两半 |
| 果冻(rolling shutter) | **反而变好** —— 强光下 AE 用短曝光，运动模糊与 skew 均减小 |

### 新增门限在此场景下是「失效安全」

光照差 → `conf` 低 → **被拒绝、不参与控制**（fail-safe），而非「拿垃圾检测打满横移」（fail-dangerous）。
但**拒绝 = 无检测 = 无修正**，靠 `safety_loss_timeout = 0.8` 切悬停兜底。**是「坏得安全」，不是「解决了」。**

### 解决方向（按性价比）

1. **锁曝光**（手动固定）替代 auto —— 一致性 > 最优亮度，控制环要的是**稳定测量**
2. **多光照采集 + 微调**模型（几百张，冻结 backbone；`models/` 已有 `.bak_ftbaseline` 前例）
3. **雷达融合（§3 档 2）** —— 从根上不依赖光照

### 验证协议（不用飞）

1. 设备搬到**阳光**下，槽置于相机下方
2. 保持 `--no-control` 只检测模式跑 2~3 分钟
3. 统计 `conf` 分布，对比台架基线 **0.87**
4. `conf` 中位 < 0.6 ⇒ 光照域偏移确认，需正面解决

## 9.6 ⚠️ 重大更正：MID-360S 在作业姿态下**看不到水槽**（2026-09-14 晚）

### 9.6.1 实测证据

对 §9.4 采集的 920,832 点做仰角分布分析：

```
仰角范围: -7.9° ~ +54.1°          ← 与 MID-360S 规格 -7°~+52° 吻合
   -5~  +0 :   59082   6.4%
   +0~  +5 :  394543  42.8%   ← 单个 10° 扇区占 42.8%
   +5~ +10 :   52131   5.7%
方位角: 全向覆盖 (最小扇区 3.2%)
```

### 9.6.2 结论：这是**选型问题**，不是配置问题

- 该雷达**基本是水平朝向的**（42.8% 的点在 ±5° 内 → 墙与周围结构）。
- 垂直 FOV 下限仅 **−7°** ⇒ 要看到脚下地面，距离须 ≥ `h/tan(7°) = 8.14·h`。
  **1.5m 高 → 12m 外。**
- **水槽在 0.5~1.5m 正下方 → 完全落在 FOV 之外。**
- ⇒ **MID-360S 是导航型雷达**（360° 水平、明显偏上看），**设计上不用于低头看近距几何**。
  **调参解决不了。**

### 9.6.3 更正 §9.4 的错误结论

§9.4「地面可测到 <10mm」**作废**。拟合出的「平面」法向 = LiDAR 的 +Z，
实为 **LiDAR 高度处的水平面**（仰角≈0 的点按定义即落在 z=0 平面），是**几何恒等式**，
**不构成测距精度证据**。**不得引用。**

### 9.6.4 架构修订：雷达看不到槽**不影响方案**

```
雷达     → 定位 + 高度          (擅长, 且光照免疫)        ✓ 已验证
单目相机 → 槽的横向偏差          (唯一能看到槽的传感器)
融合     → 世界系槽中心线        (相机 1 维偏差 × 雷达位姿, 增量建立)
飞行     → L2 纯追踪, 匀速前进
双目     → 暂不使用 (用户确认当前不可用)
```

**融合逻辑**：相机逐帧给出「槽中心相对机体的横向偏差」（1 维、局部）；
雷达给出「该时刻机体在世界系的位姿」。二者相乘 ⇒ **槽中心线被逐段钉入世界系**。
飞一遍即建出该线，后续走 L2 纯追踪，视觉仅补低带宽残差。

**雷达只需知道「我在哪」，不需知道「槽在哪」⇒ 看不到槽不构成阻塞。**

### 9.6.5 顺带修复根因 #1（mm/px 乘性噪声）

原 `mm_per_px = trough_width_mm / trough_width_px` 为**自估**，宽度一抖则 offset_mm 整体被缩放。
现可用雷达/定位的**高度 h**：下视相机 `mm_per_px ≈ h / fx` —— **稳定得多**。§2 根因 1 由此可解。

### 9.6.6 光照问题的正面解法（无传感器可免疫）

只有单目能看到槽，而单目最怕光照。**不存在既能看到槽又免疫光照的传感器。**
⇒ 光照必须正面解决：

| 手段 | 说明 | 优先级 |
|------|------|--------|
| **锁曝光** | 固定值替代 auto；控制环要的是**稳定测量**而非最优亮度 | 高 |
| **主动补光 + 窄带滤光** | **工业界标准解法**：红外/窄带光源 + 匹配滤光片 ⇒ 相机只见自身光源 ⇒ **对阳光完全免疫**。前提：相机无 IR-cut（或可拆） | **高（若可行则根治 §10）** |
| 多光照数据微调 | 几百张，冻结 backbone | 中 |
